# 05 | 確認問題・実装演習と解答

**取り組み方**：先に問題だけを読み、説明するか小さなコードを書いてから模範解答を確認してください。

## 問題

**Q1.** この課題の通信はインターネット上のUDP通信か。`AF_UNIX` と `SOCK_DGRAM` の意味を説明せよ。

**Q2.** なぜクライアントにも `sock.bind(client_path)` が必要か。

**Q3.** `sock.recvfrom(4097)` は何を返すか。`received, _` の `_` とは何か。

**Q4.** `len('あ')` と `len('あ'.encode('utf-8'))` の違いは何か。

**Q5.** `send_message()` の `try/finally` の目的は何か。

**Q6.** `input_messages()` 内の `yield message` と `return message` の違いは何か。

**Q7.** `make_reply(message, fake)` の返答は質問内容に応じて変わるか。

**Q8.** `client.py` と `src/client.py` が分かれているのはなぜか。

**Q9.** `--message 'こんにちは'` と対話モードは何が違うか。

**Q10.** 現状のサーバーは複数クライアントを同時に並列処理できるか。

### 改修課題 A

`src/server.py` の `make_reply` を、返信の先頭に `[自動返信] ` を付けるように変更する（Fakerの文生成は残す）。どの行を変えればよいか。

### 改修課題 B

受信した文字列の前後の空白を削除してログ表示するには、`src/server.py` のどこで何を呼び出せばよいか。

### 改修課題 C

通信のタイムアウト秒数をCLIから10秒に変更するコマンドを書け。

---

## 詳細解答

**A1.** インターネット上のUDPではない。`AF_UNIX` は同一マシン内部のアドレスファミリー、`SOCK_DGRAM` はデータグラム型の通信である。双方の組合せでUNIXドメインのデータグラム通信になる。

**A2.** サーバーは `recvfrom()` で得た送信元アドレスへ `sendto()` して返信する。クライアントが自身の受信可能なアドレス（パス）を `bind()` していなければ、サーバーの返送先を確保できない。

**A3.** `(受信したbytes, 送信元アドレス)` のタプルを返す。`_` は返信元のアドレスを後続で使用しない意図を表す慣用的な変数名。4097バイト指定は最大4096バイトを超えたデータの検出に使う。ただし受信バッファより長いデータは切り詰められる可能性があるため、それより大きい長さそのものまでは分からない。

**A4.** `len('あ') == 1` は文字数。UTF-8にエンコードした `bytes` の長さは3。送受信のサイズ上限は後者で判定する。

**A5.** 送信・受信で例外が発生しても `sock.close()` と `unlink_socket(client_path)` を試み、一時的なOSリソースが残るのを防ぐ。

**A6.** `yield` は呼び出し元に1件を渡して中断位置を保持する。次に反復すると入力処理を続けられる。`return` では関数が終了し、連続入力用のジェネレーターとしては機能しない。

**A7.** いいえ。現状の `make_reply` は引数 `message` を利用せず `fake.sentence(...)` を呼ぶ。文字列はランダム生成であり、会話の意味に対応しない。

**A8.** ルートの `client.py` は起動入口、`src/client.py` は実装本体。依存と処理を分け、テストから関数をimportしやすくするため。

**A9.** `--message` 指定時は1件だけ送信する。省略時は `input_messages()` が入力を繰り返し、`/quit` 等まで複数回送信する。

**A10.** 受信ループは一つで、返信も同じスレッドで逐次処理する。複数クライアントが送信することは可能でも、サーバー内の返信処理を並列に実行する構造ではない。

**改修A 模範解答**：`src/server.py` の `return fake.sentence(nb_words=8)` を `return '[自動返信] ' + fake.sentence(nb_words=8)` に変更する。Fakerによる生成と文字列連結を組み合わせる。テストも期待する接頭辞に変更すると良い。

**改修B 模範解答**：`message = decode_message(payload)` の直後に `message = message.strip()` を追加すると、以降のログと `make_reply()` への入力の前後の空白が取り除かれる。改行や空白文字も対象になることに注意。

**改修C 模範解答**：`.venv/bin/python client.py --timeout 10 --message 'こんにちは'`。`argparse` が10を `float` に変換し、`sock.settimeout(10.0)` に渡す。
